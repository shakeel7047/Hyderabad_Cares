# FixMyHyderabad

A civic reporting website for **Hyderabad, Sindh** — same theme structure and
reporting pattern as the reference site, with a new brand, new palette, and all
original content.

- Hero photo: Navalrai Clock Tower (Ghanta Ghar), Hyderabad
- Live map: Leaflet + OpenStreetMap, centred on Hyderabad
- Backend: plain PHP 8 + MySQL (PDO) for report submissions
- Pages: Home, Report an issue, Map, City stats, About, Help, Privacy, Terms
- Language: English, same tone/pattern as the reference site

> Demo content: stats on the home and stats pages are sample data. Report
> submissions are saved to MySQL and appear on the map when the PHP API and
> database are configured. Sample report cards remain as a fallback if the API
> cannot load.

---

## Local development (XAMPP)

1. Install XAMPP with Apache, PHP, and MySQL.
2. Clone this repository into XAMPP's document root (usually
   `C:\xampp\htdocs\hyderabad-cares`), or copy the project folder there.
3. Start Apache and MySQL from the XAMPP Control Panel.
4. Open **http://localhost/hyderabad-cares/**.

The HTML pages can be previewed without a database, but report submission and
live reports require the PHP/MySQL setup below. GitHub Pages serves static
files only and cannot run this project's PHP API.

The HTML pages are generated by `tools/build-hyderabad.mjs` in the repo root:

HTML directly also works — just do not re-run the builder afterwards, or your
direct edits will be replaced by the template content.

## Live map

`map.html` uses Leaflet 1.9.4 from unpkg and OpenStreetMap tiles:

- Map centre: `25.3960, 68.3578` (Hyderabad, Sindh), zoom 13
- Markers and list rows are fetched from `api/reports.php?limit=200`
- Each report is placed near its area centre with a small deterministic offset;
  the page says clearly that marker positions are approximate
- Category filter buttons dim non-matching markers **and** hide list rows
- If the API cannot load, the server-rendered sample rows stay visible and a
  warning explains that live data is unavailable
- If Leaflet or the CDN is unavailable, a fallback message is shown and the
  report list still works

To make the map fully self-hosted (no CDN), download Leaflet's CSS/JS and the
marker images into `assets/vendor/leaflet/` and update the two URLs in
`map.html` and the build script.

Map data © OpenStreetMap contributors (ODbL).

## Backend (PHP + MySQL)

The report form posts to `api/reports.php`. It uses plain PHP 8.2 and PDO — no
framework, no Composer, no Node on the server.

### Local setup

XAMPP defaults are used: host `127.0.0.1`, user `root`, empty password,
database `fixmyhyderabad`.

The database and table were created with the one-time installer, which has now
been deleted. If you ever need to recreate them:

1. Open **phpMyAdmin** → **Import** → choose `api/schema.sql` → **Go**.
2. Make sure `api/uploads/` exists and is writable.

If you change the database name, user, or password, edit `api/config.php`.

### Endpoints

```
GET  api/reports.php
GET  api/reports.php?category=roads&area=Latifabad&status=Reported&limit=50
POST api/reports.php        (multipart/form-data — the report form)
```

`GET` returns public fields only. `reporter_name`, `contact`, and `ip_hash` are
never exposed. `limit` is clamped to `1–200`.

`POST` requires:

| Field | Rule |
|---|---|
| `category` | one of the eight category keys |
| `area` | one of the 14 covered areas |
| `landmark` | 3–160 characters |
| `title` | 5–120 characters |
| `details` | 15–1200 characters (stored up to 2000) |
| `consent` | must be present |
| `photo` | optional; JPG, PNG, or WebP; max 5 MB |
| `name`, `contact` | optional, stored privately |
| `website` | honeypot — must stay empty |

Responses use `{"ok":true,…}` or `{"ok":false,"error":"…"}`. A successful
create returns `201` and a public ID such as `FMH-2026-1842`.

### Safety built in

- Prepared statements everywhere; all output escaped in the browser.
- Honeypot field for bots.
- Throttle: max **5 reports per IP hash per 10 minutes** (returns `429`).
- Photos get a random filename; `api/uploads/.htaccess` blocks PHP execution and
  directory listing.
- MIME type checked with `finfo`, not the file extension.

### Change a report's status

There is no admin UI yet. Use phpMyAdmin or SQL:

```sql
UPDATE reports SET status = 'Verified' WHERE public_id = 'FMH-2026-1842';
-- Allowed: Reported, Verified, Progress, Resolved
```

## Before going live

1. **Database:** edit `api/config.php` with the live host, database name, user,
   and password. Import `api/schema.sql` once.
2. **Replace demo stats:** the home KPI strip and `stats.html` are still sample
   numbers. Replace them with a query or remove the page until you have data.
3. **Email:** replace `hello@fixmyhyderabad.example` in the build script and
   `mailto:` links.
4. **Privacy / Terms:** review with a lawyer, fill in placeholders.
5. **“Who runs it?”** section on About: add your real team details.
6. **Remove the demo-data notices** once real data is connected.
7. **Backups:** schedule database + uploads backups if you expect real reports.

## Uploading to Hostinger (Business plan)

1. hPanel → **File Manager** → open `public_html`
2. Upload the **contents** of this project (not the folder itself):
   all `.html` files, `assets/`, and `api/`
3. hPanel → **Databases** → create a MySQL database and user; note the host,
   database name, user, and password
4. In `api/config.php`, set those credentials (Hostinger usually uses
   `localhost` as the DB host)
6. phpMyAdmin → select the new database → **Import** → `api/schema.sql`
7. Make sure `api/uploads/` is writable (permissions `755` or `775`)
8. Test the form once, confirm the row appears in phpMyAdmin and on the map
9. Enable free SSL and force HTTPS
10. Take a backup after the first successful upload

The `api/` folder requires PHP (8.1+ recommended) and MySQL. The HTML, CSS, JS,
fonts, and images are plain static files.
